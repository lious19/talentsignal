What review caught7
Defect 1 · S-01

The cold-start race

All three containers started at once. PostgreSQL takes seconds to accept connections — so the API would come up, try to connect, and fail.

depends_on waits for a container to start, not to be ready. That distinction is not obvious, and it bites almost everyone.

Fixed  pg_isready healthcheck + depends_on: condition: service_healthy

Defect 1 — cold-start race8
Defect 2 · S-02

Privilege escalation

The plan had registration accept a role from the request body.

{ "role": "admin" }

Anyone could have made themselves an administrator.

Fixed  Registration hardcodes sales. Admin bootstrapped from environment variables at boot.

Defect 2 — privilege escalation9
Defect 3 · S-01

The logger went silent

It listened for finish — which only fires when a response completes normally.

Close the tab mid-request and finish never fires. No log line at all.

The defect was inside the safety feature itself — the one thing meant to make failures visible was invisible in exactly the case that mattered.

Fixed  Also listen for close; use writableEnded to tell completed from aborted.

Limits

What I have not proven

  • The job board is mocked. Real, but behind an interface — one line to swap.
  • The confidence weights are unapproved. Mine, flagged, pending the client.
  • Roles exist but nothing enforces them. That is S-14.
  • Nothing is deployed. It has never faced the internet. That is S-20.
  • Performance is unmeasured. I will not claim a number I have not tested. That is S-18.

I would rather say "I haven't measured that"
than guess in front of you.
