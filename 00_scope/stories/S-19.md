## Story
As the platform team, I want end-to-end tests over the real stack, deterministic seed data,
and a CI pipeline, so every change is proven green before merge and the demo is reproducible
from a clean checkout.

## Slice
End-to-end tests exercising the critical user journeys against the real HTTP + Postgres stack;
a deterministic seed command for a demo dataset; and a GitHub Actions workflow that runs
migrations + unit + integration + E2E + tsc/lint on every push/PR as a required green gate.

## Acceptance (Gherkin)
- **E2E over the real stack** — Given a freshly migrated database and the seed dataset; When the
  critical journeys run (login → hidden-demand analyze → opportunities → hard-to-fill targeting;
  and client-matchmaking / recommendation-engine / package draft+release); Then they pass
  end-to-end against the actual API + DB, not mocks.
- **Deterministic seed** — Given the seed command against an empty DB; Then it populates a fixed
  demo dataset (clients, candidates, job openings, and at least one hard-to-fill opportunity so
  HF-2/HF-3 have something to show), identically every run.
- **CI green gate** — Given a push/PR; When CI runs; Then it stands up Postgres, runs migrations,
  runs unit+integration+E2E, and enforces tsc + lint; a failure blocks merge.
- **🛡 TRUST — the gate proves the guardrails, not just happy paths.** The trust-scenario tests
  already in the suite (no-outbound, append-only audit, human-release / no-auto-submit incl.
  HF-3) run in CI and must pass, so the "AI drafts, a human releases" rule is enforced on every
  change, not just asserted once.

## Build note
Reuse the existing test harness, `SeedJobBoardProvider`, and `db/seedAnalyticsDemo.ts` rather
than duplicating. E2E via supertest against a real migrated DB (or docker compose). Add
`.github/workflows/ci.yml` with a `postgres` service, `DATABASE_URL`/`JWT_SECRET` from CI secrets
(never committed). Keep S-18's opt-in load harness OUT of CI (it's non-blocking by design —
`scripts/` is outside `tests/`, and CI must not set `RUN_TIMING_TESTS=1`).

## Judgment calls to log (decision, pending Ali)
Resolved in `06_decisions/029-e2e-seed-and-ci-gate-scope.md` (PROPOSED, pending Ali):
- **E2E-critical journeys (both named verbatim in this story's Gherkin):** (a) register → login →
  hidden-demand analyze → opportunities → hard-to-fill targeting; (b) client/job/candidate
  creation → client-matchmaking → recommendation-engine (+feedback) → opportunity-package
  draft → release. Every other router already has direct integration coverage and doesn't need a
  second cross-endpoint proof.
- **CI enforcement is a real behavior change, not just new files:** setting `DATABASE_URL` in CI
  turns every currently-self-skipping `*.integration.test.ts` / `*.appendOnly.integration.test.ts`
  / `migrate.test.ts` into a required blocking gate for the first time, with zero code changes to
  those files.
- **Perf-threshold enforcement: deferred again, not picked up.** The `*.latency.integration.test.ts`
  files stay diagnostic-only (`RUN_TIMING_TESTS=1`, never set by CI) — a hard latency assertion on
  a shared CI runner is a flakiness risk this close to the deadline, and no CI perf budget is
  agreed with Ali yet.
- **Lint = `tsc -p tsconfig.ci.json --noEmit`** (new config, also covers `tests/`, which
  `tsconfig.json` excludes today) — chosen over standing up ESLint same-day, given zero ESLint
  infra exists anywhere in the repo. Real ESLint logged as a fast-follow, not dropped.
- **Seed dataset:** small and deterministic (~26 seeded clients reused from `seedAnalyticsDemo.ts`
  + ~6-8 candidates + a 9-row hard-to-fill batch via the real scorer) — for CI speed and so a
  re-run always converges on the same rows.

## Watch-points
No secrets in the workflow (CI secrets only). CI must run migrations against a clean schema each
run. Don't let CI pull in the load test or `RUN_TIMING_TESTS`. Keep the E2E dataset small so the
gate stays fast.

## Tests
The E2E suite itself is the deliverable's test; plus a check that the seed command is idempotent/
deterministic, and that CI fails red when a trust-scenario test is broken (proves the gate bites).
