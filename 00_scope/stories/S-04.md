# S-04 — Hidden Demand Analysis service
**Agent:** SignalAgent · **Fulfills:** REQ-001, REQ-019 · **Due:** Mon Jul 27
**Basecamp:** https://app.basecamp.com/3945211/buckets/24865175/todos/10116038189

## Story
As a sales rep, I want the platform to rank companies by likely hidden staffing demand so
I engage the right ones first.

## Slice
`POST /api/hidden-demand/analyze` → `DemandScored` → ranked opportunities with confidence
and contributing factors

## Acceptance (Gherkin)
**Ranked, explainable opportunities**
- Given a batch of ingested signals in PostgreSQL
- When analysis runs
- Then opportunities come back ranked by a bounded confidence score with the factors that
  drove it

**Bounded latency on the seed set**
- Given up to 10000 seed records
- When analysis runs
- Then it returns within the 5s target (AC-4-2)

**🛡 TRUST — The platform never contacts a client on its own**
- Given a high-confidence opportunity
- When it is detected
- Then the system only surfaces it to a human; it sends nothing outbound automatically

## Build note (Ali's words)
> Implement the scoring heuristic behind a service boundary (swappable for a real model
> later), persist contributing factors, and expose ranked results to the React demand board.

**Vibe-code it:** Score first, learn later. A transparent heuristic a human trusts beats an
opaque model they don't.

## What this actually is (important)
S-03 already built the scorer (`confidenceScore.ts`) and the upsert. S-04 is **not a new
scorer** — it is: (1) reuse that scorer over a *batch*, (2) rank the results, (3) a seed
set big enough to demo and to hit the latency target, (4) a React demand board, (5) proof
that nothing goes outbound. Do not let Claude Code build a second, parallel scoring engine.
