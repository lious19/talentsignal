## Story
As a compliance officer, I want consent, encryption, an append-only audit trail, and data
access/erasure requests so the agency meets GDPR and CCPA.

## Slice
`POST /api/privacy/request` → `PrivacyRequestLogged` → an append-only audit log and a
data-request queue

## Acceptance (Gherkin)
**Right to access and erasure**
- Given a candidate data request
- When it is submitted
- Then the request is queued, actioned, and every step is recorded in the append-only audit log

**🛡 TRUST — The audit log cannot be rewritten**
- Given an audit entry
- When anyone attempts to edit or delete it
- Then the operation is refused; the log is append-only by constraint

## THE VICTORY LAP — this reads foundations you already built
1. **Append-only AuditLog** — REUSE the S-08 append-only trigger pattern
   (sales_pipeline_audit, opportunity_package_release_audit). The trust scenario ("cannot
   be rewritten") is the SAME one S-08 already proves with a DB-gated test. Don't reinvent —
   apply the proven trigger to a general AuditLog table.
2. **Erasure reads the `pii_fields` registry (S-05).** Honoring "delete everything you hold
   on me" = loop over the registered PII columns and apply each one's `erasure_strategy`
   (`reset_to_empty`, `anonymize`, `retain_exempt`). This is the payoff of every PII tag you
   made. If the registry is complete, erasure "just works" by looping it.

## The four parts
1. **Append-only AuditLog** (above) — general privacy-event audit, S-08 trigger reused.
2. **Consent flag on personal data** — a consent field (on candidates, maybe clients), and
   personal-data use gated on it. WHERE consent is checked and WHAT it gates is a policy call.
3. **Encryption at rest/in transit — CONFIG.** Note Ali says "config." At-rest is
   infra-level (disk/Postgres), in-transit is TLS. For the demo this is a documented,
   configured approach — be honest about what's demo-scoped vs production. Do NOT fake or
   hand-roll encryption.
4. **Privacy-request workflow (React)** — submit an access OR erasure request → queued →
   actioned → every step written to the append-only audit log. Access returns the PII held on
   that person (from the registry); erasure applies the registry strategies.
